In brief

This is a free INEMA kit in Portuguese for people studying security who want an open AI model that does not refuse technical questions. These are called abliterated models: their refusal behavior has been removed. The kit shows how to connect one to DeepSeek Harness (an open source agent) through an API, a rented RunPod GPU, or LM Studio on your computer. It includes ready-to-use prompts, scripts that check whether text, tools, and images work, a fake lab for practice, and a guard that stops an idle GPU. You need an assistant that can read files, Python 3.10+, and, depending on the option, an API or GPU account — plus permission for everything you test.

What it is

A model that does not refuse, with boundaries you control

Removing a model’s refusal behavior does not remove your responsibility. Responsibility shifts to the scope, the lab, and the permissions you grant. The kit provides all three.

🧭 Three options, one test

Hosted API, RunPod GPU, or local LM Studio. For each, the same checker confirms text over two turns, a harmless function, and image reading — each tested separately.

🧪 A lab before the real world

A fake page at 127.0.0.1 with two configuration issues. The check runs only with a valid scope file, sends one request, and rejects any remote host.

💸 The GPU does not stay on for no reason

A local guard tracks idle time and, when you tell it to, stops your Pod after checking its ID and name — starting with a simulation and confirming EXITED.

How it works

Choose an option, verify each layer, then use it

The order is always the same: scope and lab first, one capability at a time, costs under control.

Read the boundaries→ Choose an option→ Connect to Harness→ Test text · function · image→ MCP tools→ Synthetic lab→ Your app, within scope

Prerequisites

What you need

The kit’s scripts use only Python’s standard library. Everything else depends on the option you choose.

Python 3.10+ and git

To download the kit and run its scripts and tests.

git clone https://github.com/inematds/ia-sem-censura-defensiva
cd ia-sem-censura-defensiva
python3 kit/scripts/doutor.py

An assistant that can read files

Claude Code, Codex, or a similar tool. It follows the prompts and shows you what it will do first. Node.js in the version required by Harness.

An account for your option

API: provider account and credits. RunPod: account and credits. Local: free memory and disk space. Chat subscriptions include neither API access nor GPU.

User guide · step by step

From scratch to your first lab finding

Steps 1 to 4 work today without any account. From step 5 onward, follow the prompts for your chosen option.

1

Download the kit and check your machine

The doctor script only reads versions and ports; it does not install anything or open a key.

git clone https://github.com/inematds/ia-sem-censura-defensiva && cd ia-sem-censura-defensiva
python3 kit/scripts/doutor.py
2

Run the offline tests

25 tests at 127.0.0.1 using fake servers: denied scope, rejected remote target, expired scope, finding and fix, proxy without a token, idle timer, and stop failure.

python3 -m unittest discover -s kit/testes -v   # Ran 25 tests ... OK
3

Start the lab and run a scoped check

Use two terminals. The check creates a 10-minute scope for your lab only, sends one request, and lists the findings.

# terminal 1
python3 kit/scripts/laboratorio.py
# terminal 2
python3 kit/scripts/checagem_segura.py --lab-local-autorizado
# "findings": X-Content-Type-Options and Referrer-Policy are missing
4

Fix the issues and test again

Stop the lab (Ctrl+C), start the fixed version, and repeat the same check. Use the report template (in Portuguese) to separate evidence, hypothesis, and fix.

python3 kit/scripts/laboratorio.py --corrigido
python3 kit/scripts/checagem_segura.py --lab-local-autorizado   # "findings": []
5

Give the kit to your assistant

Open CONFIGURA-COM-ASSISTENTE.md (in Portuguese), copy the request, and paste it into Claude Code (or a similar tool) opened in the kit folder. It asks about your option, free memory, and budget.

6

Connect the model using your option

Follow the numbered prompts (in Portuguese). For the local option, the server is bound to 127.0.0.1:

lms load SEU-MODELO --context-length 4096 --identifier defensivo-local --ttl 600
lms server start --bind 127.0.0.1 --port 1234
7

Verify text, function, and image

If needed, the key comes from a private file, never from chat. Each capability produces a separate result.

# for API or cloud only; local endpoint does not need this
export INEMA_CHAVE_MODELO_ARQ=~/.segredos/chave-modelo   # file with chmod 600
python3 kit/scripts/checa_endpoint.py --base-url http://127.0.0.1:1234/v1 \
  --modelo defensivo-local --funcao --imagem kit/exemplos/teste-visao.png
8

Add tools, one at a time

Browser (Playwright MCP), research (Firecrawl MCP), and Nuclei: test each with a real call. Run Nuclei only against the lab, using the kit’s passive template.

nuclei -u http://127.0.0.1:8181/ -t kit/exemplos/nuclei-cabecalhos-lab.yaml -rl 1 -c 1
9

On RunPod: simulate the idle guard

Every request goes through the guard at 127.0.0.1:8282, with a local token. Only after you see simulacao_pararia should you enable the actual stop, using the Pod’s exact ID and name. Check for EXITED in the dashboard.

export INEMA_TOKEN_LOCAL_ARQ=~/.segredos/token-guarda
python3 kit/scripts/guarda_ociosa.py --upstream https://SEU-ENDPOINT/v1 --ocioso 900
10

Your app, with written scope only

Fill out a copy of escopo-autorizado.exemplo.json (in Portuguese) outside the repository and use prompt 09: a non-destructive plan, minimal evidence, a fix, and a retest.

Boundaries

The rules that come with a model that does not refuse

They appear at the end of every prompt and in USO-DEFENSIVO.md (in Portuguese). They are required.

Only what belongs to you

Systems you own or have the owner’s written permission to test. A public URL, working login, or API key is not permission.

Scope before the first request

Exact target, documented permission, actions, time window, and limits. If anything is missing, expired, or unclear: stop.

Start with a synthetic lab

Made-up data at 127.0.0.1. Run checks that change nothing before anything else.

Evidence in proportion

Use the smallest amount of evidence that confirms a finding. Do not download a database, expose real credentials, or access someone else’s account.

Keep credentials out of chat and git

Use a private file with chmod 600, pointed to by an environment variable. Use test keys and revoke them at the end.

A prompt is not a boundary

Run a downloaded model without tools first. Isolation comes from the operating system and container, not the prompt text.

Keep local services on 127.0.0.1

An endpoint on your computer must not be open to the network. Always authenticate a cloud endpoint — verify that requests without a key are rejected.

Stop the Pod and check EXITED

Stopping the app does not stop the GPU. Storage keeps charging even when the Pod is stopped.

AI makes mistakes: verify

An AI finding is a hypothesis until you reproduce it safely. A clean scan does not prove something is safe.

Security research on backdoors in abliterated models: ProjectDiscovery — How abliterated models can get you pwned (in English).
