En resumen

Este es un kit gratuito de INEMA, en portugués, para quienes estudian seguridad y quieren un modelo de IA abierto que no rechace preguntas técnicas: los llamados modelos abliterated, a los que se les quitó el rechazo. Muestra cómo conectar este modelo a DeepSeek Harness (un agente de código abierto) por API, mediante una GPU alquilada en RunPod o con LM Studio en tu computadora. Incluye prompts listos, scripts que comprueban si funcionan el texto, las herramientas y las imágenes, un laboratorio simulado para practicar y una protección que detiene la GPU cuando está inactiva. Necesitas un asistente que lea archivos, Python 3.10+ y, según la ruta, una cuenta de API o de GPU, además de permiso para todo lo que pruebes.

Qué es

Un modelo que no rechaza, con límites que tú controlas

Quitarle el rechazo al modelo no elimina la responsabilidad: esta recae en el alcance, el laboratorio y los permisos que le das. El kit incluye esas tres cosas listas.

🧭 Tres rutas, una prueba

API alojada, GPU en RunPod o LM Studio local. En todas, el mismo verificador comprueba el texto en dos turnos, una función inofensiva y la lectura de una imagen, cada una por separado.

🧪 Primero el laboratorio, después el mundo real

Una página falsa en 127.0.0.1 con dos problemas de configuración. La comprobación solo se ejecuta con un archivo de alcance válido, hace una solicitud y rechaza cualquier host remoto.

💸 La GPU no queda encendida sin motivo

Una protección local mide el tiempo de inactividad y, si se lo indicas, detiene tu Pod tras comprobar el ID y el nombre, primero en modo de simulación y verificando EXITED.

Cómo funciona

Elige la ruta, comprueba cada capa y luego úsala

El orden siempre es el mismo: primero el alcance y el laboratorio, luego una capacidad a la vez y el costo bajo control.

Requisitos previos

Qué necesitas tener a mano

Los scripts del kit usan solo la biblioteca estándar de Python. El resto depende de la ruta.

Python 3.10+ y git

Para descargar el kit y ejecutar los scripts y las pruebas.

git clone https://github.com/inematds/ia-sem-censura-defensiva
cd ia-sem-censura-defensiva
python3 kit/scripts/doutor.py

Un asistente que lea archivos

Claude Code, Codex o similar. Sigue los prompts y te muestra lo que hará antes de hacerlo. Node.js en la versión que requiera el Harness.

Una cuenta según la ruta

API: cuenta y crédito en el proveedor. RunPod: cuenta y crédito. Local: memoria disponible y espacio en disco. Ninguna suscripción de chat incluye API o GPU.

Guía de uso · paso a paso

Desde cero hasta el primer hallazgo en el laboratorio

Los pasos 1 a 4 funcionan hoy, sin ninguna cuenta. A partir del 5, sigue los prompts de tu ruta.

1

Descarga el kit y comprueba el equipo

El diagnóstico solo lee versiones y puertos; no instala nada ni abre claves.

git clone https://github.com/inematds/ia-sem-censura-defensiva && cd ia-sem-censura-defensiva
python3 kit/scripts/doutor.py
2

Ejecuta las pruebas offline

25 pruebas en 127.0.0.1 con servidores falsos: alcance denegado, objetivo remoto rechazado, alcance vencido, hallazgo y corrección, proxy sin token, reloj de inactividad y fallo al detener.

python3 -m unittest discover -s kit/testes -v   # Ran 25 tests ... OK
3

Inicia el laboratorio y haz la comprobación con alcance

Usa dos terminales. La comprobación crea un alcance de 10 minutos solo para tu laboratorio, hace una solicitud y enumera los hallazgos.

# terminal 1
python3 kit/scripts/laboratorio.py
# terminal 2
python3 kit/scripts/checagem_segura.py --lab-local-autorizado
# "achados": faltan X-Content-Type-Options y Referrer-Policy
4

Corrige y vuelve a probar

Detén el laboratorio (Ctrl+C), inicia la versión corregida y repite la misma comprobación. Usa la plantilla de informe (en portugués) para separar evidencia, hipótesis y corrección.

python3 kit/scripts/laboratorio.py --corrigido
python3 kit/scripts/checagem_segura.py --lab-local-autorizado   # "achados": []
5

Entrega el kit a tu asistente

Abre CONFIGURA-COM-ASSISTENTE.md (en portugués), copia la solicitud y pégala en Claude Code (o similar), abierto en la carpeta del kit. Te preguntará qué ruta eliges, cuánta memoria tienes libre y cuál es tu presupuesto.

6

Conecta el modelo mediante la ruta que elegiste

Sigue los prompts numerados (en portugués). En la ruta local, el servidor queda limitado a 127.0.0.1:

lms load SEU-MODELO --context-length 4096 --identifier defensivo-local --ttl 600
lms server start --bind 127.0.0.1 --port 1234
7

Comprueba el texto, la función y la imagen

Si hay una clave, debe venir de un archivo privado, nunca del chat. Cada capacidad se informa por separado.

# solo para API o nube; el endpoint local no lo necesita
export INEMA_CHAVE_MODELO_ARQ=~/.segredos/chave-modelo   # archivo con chmod 600
python3 kit/scripts/checa_endpoint.py --base-url http://127.0.0.1:1234/v1 \
  --modelo defensivo-local --funcao --imagem kit/exemplos/teste-visao.png
8

Añade herramientas, una a la vez

Navegador (Playwright MCP), búsqueda (Firecrawl MCP) y Nuclei, cada uno comprobado con una llamada real. Nuclei solo se ejecuta contra el laboratorio y con la plantilla pasiva del kit.

nuclei -u http://127.0.0.1:8181/ -t kit/exemplos/nuclei-cabecalhos-lab.yaml -rl 1 -c 1
9

En RunPod: prueba la protección de inactividad en modo de simulación

Todas las solicitudes pasan por la protección en 127.0.0.1:8282, con un token local. Cuando veas simulacao_pararia, puedes activar la detención real con el ID y el nombre exactos del Pod. Comprueba EXITED en el panel.

export INEMA_TOKEN_LOCAL_ARQ=~/.segredos/token-guarda
python3 kit/scripts/guarda_ociosa.py --upstream https://SEU-ENDPOINT/v1 --ocioso 900
10

Usa tu app solo con el alcance por escrito

Completa una copia de escopo-autorizado.exemplo.json (en portugués) fuera del repositorio y usa el prompt 09: plan no destructivo, evidencia mínima, corrección y nueva prueba.

Límites

Las reglas que acompañan al modelo sin rechazo

Están al final de todos los prompts y en USO-DEFENSIVO.md (en portugués). No son opcionales.

Solo lo que es tuyo

Sistemas tuyos o cuyo dueño te haya dado permiso por escrito. Una URL pública, un inicio de sesión válido o una clave de API no son permisos.

Define el alcance antes de la primera solicitud

Objetivo exacto, permiso registrado, acciones, horario y límites. Si falta algo, venció o no está claro: detente.

Primero, el laboratorio sintético

Datos inventados en 127.0.0.1. Antes que nada, haz comprobaciones que no cambien nada.

Pruebas proporcionales

La menor evidencia que confirme el hallazgo. No descargues bases de datos, no muestres credenciales reales ni accedas a cuentas ajenas.

Credenciales fuera del chat y de git

Usa un archivo privado con chmod 600, indicado mediante una variable de entorno. Revoca las claves de prueba al terminar.

Un prompt no es una barrera

Primero ejecuta el modelo descargado sin herramientas. El aislamiento depende del sistema operativo y del contenedor, no del texto del prompt.

Usa 127.0.0.1 solo en local

El endpoint de tu computadora no debe estar abierto en la red. Protege siempre con autenticación el endpoint en la nube y comprueba que rechace las solicitudes sin clave.

Detén el Pod y comprueba EXITED

Detener la app no detiene la GPU. Y el almacenamiento sigue generando cargos aunque el Pod esté detenido.

La IA se equivoca: comprueba los resultados

Un hallazgo de IA es una hipótesis hasta que se reproduce de forma segura. Una exploración sin resultados no demuestra que algo sea seguro.
